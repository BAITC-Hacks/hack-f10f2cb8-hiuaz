## 2. Mac-та алғашқы орнату

### 2.1. Терминал мен Python-ды тексеру

macOS-та **Terminal** ашып, орындаңыз:

```bash
python3 --version
git --version
uname -m
sw_vers
```

Тексерілген комбинация: `Python 3.9.6`, `x86_64`, macOS `12.7.6`. Git жоқ болса, `git --version` ұсынған Apple Command Line Tools орнатуын аяқтаңыз. Python табылмаса, алдымен Python орнату қажет; бұл репозиторийде Python орнатқышы жоқ.

### 2.2. Репозиторийді алу

```bash
git clone https://github.com/BAITC-Hacks/hack-f10f2cb8-hiuaz.git
cd hack-f10f2cb8-hiuaz/khattama-ai
```

Жоба бұрын жүктелген болса, қайта көшірме жасамай, оның `khattama-ai` қалтасын ашыңыз. **Төмендегі барлық командалар осы қалтадан орындалады.** Қате шыққан қадамды шешпей, келесісіне өтпеңіз.

### 2.3. Кітапханаларды орнату

```bash
bash install_mac.sh
```

Скрипт жергілікті `.venv` ортасын құрады, тәуелділіктерді орнатады, `pip check` пен диагностика жүргізеді. Жүйелік Python пакеттерін ауыстырмайды; `sudo pip` қолдану қажет емес. Нақты орнатылған нұсқалар `installed_versions.txt` файлына жазылады.

Бұл қадамда модельдер әлі жүктелмегендіктен, `MODEL … не скачана` шығуы қалыпты. Кітапхана импортының `ERROR` қатесін алдымен түзету керек.

### 2.4. Модельдерді жүктеу

```bash
.venv/bin/python prepare_models.py
```

Жүктелетін құрамдастар: Whisper small, сөйлеу шекараларын бөлу моделі, TitaNet Small дауыс моделі және Qwen2.5-3B-Instruct Q4_K_M. Файлдар `models/` ішінде қалады. Бұл қадам интернетті пайдаланады және жиналыс файлдарын ашпайды.

Қажет бөлікті жеке жүктеуге болады:

```bash
.venv/bin/python prepare_models.py --only asr
.venv/bin/python prepare_models.py --only diarization
.venv/bin/python prepare_models.py --only llm
```

Жүктеу үзілсе, тиісті команданы қайталаңыз; дайын файлдар қайта пайдаланылады. Скрипт `models/manifest.json` ішіне SHA256 бақылау сомаларын жазады. Ол эталонмен автоматты салыстыру немесе әр іске қосқанда тұтастық тексеруі емес.

### 2.5. Орнатуды тексеру және ашу

```bash
.venv/bin/python doctor.py
.venv/bin/python -m pip check
bash start.sh
```

`doctor.py` барлық жеті кітапханаға `OK` және барлық төрт модельге `MODEL … OK` көрсетуі керек. Тек команданың сәтті аяқталуына сүйенбеңіз: модель жоқ болса да, диагностика нөлдік шығу кодын қайтара алады. `pip check` нәтижесі — `No broken requirements found.`

Браузерде **http://127.0.0.1:8501** ашыңыз. Mac-та екінші терминалдан ашуға болады:

```bash
open http://127.0.0.1:8501
```

Сервер тұрған терминалды ашық қалдырыңыз. Алғашқы модельдік өңдеу кезінде модельдер жадқа жүктеледі; басты беттің ашылуы ЖИ сапасының тексерілгенін білдірмейді.

## 3. Күнделікті іске қосу және негізгі командалар

Қайта қолданғанда `khattama-ai` қалтасынан орындаңыз:

```bash
bash start.sh
```

Тоқтату — сол терминалда **Ctrl+C**. Сақталған хаттамалар келесі ашқанда орнында қалады. Орнатуды немесе модель жүктеуді әр жолы қайталау қажет емес.

| Әрекет | Команда |
|---|---|
| Қолданбаны ашу | `bash start.sh` |
| Тәуелділіктер мен модель файлдарын тексеру | `.venv/bin/python doctor.py` |
| Пакеттер арасындағы қайшылықты тексеру | `.venv/bin/python -m pip check` |
| Модельдерді толық жүктеу | `.venv/bin/python prepare_models.py` |
| Басқа портта іске қосу | `.venv/bin/python server.py --port 8502` |
| Жұмыс істеп тұрған серверді тексеру | `curl http://127.0.0.1:8501/api/health` |
| Python тесттерін орындау | `.venv/bin/python -m unittest discover -s tests -v` |

Басқа порт қолдансаңыз, браузер мен `curl` мекенжайындағы портты да ауыстырыңыз. Барлық модель файлдары бар сервердің жауабы:

```json
{"ok": true, "models_ready": true}
```

Бұл жауап сервер мен модель файлдарының барын көрсетеді; модельді нақты шақыру сынағын алмастырмайды. `.venv/bin/python` жолы көрсетілгендіктен, виртуалды ортаны бөлек белсендіру қажет емес.

## 4. Қолданушы қалай жұмыс істейді?

### Жиналыс жазбасынан хаттама алу

1. Жоғарғы бөліктен **ҚАЗ** немесе **РУС** таңдаңыз. Интерфейс тілі сақталады; ол жаңа қорытынды мен тапсырмаларға берілетін тілдік нұсқауды және DOCX тақырыптарын анықтайды. Бұрынғы хаттама мәтіні тіл ауыстырғанда автоматты аударылмайды.
2. **«Жаңа жиналыс» / «Жазбаны жүктеу»** батырмасын басыңыз. Атауын енгізіңіз. Жиналыс күні белгісіз болса, бос қалдырыңыз; қатысушылар тізімі міндетті емес.
3. **«Аудио / бейне»** қойындысында файл таңдаңыз. Қабылданатын кеңейтімдер: MP3, WAV, M4A, MP4, OGG, FLAC, WEBM. Файлда оқылатын дыбыс жолы болуы керек. Лимит — **64 МБ және 10 минут**.
4. Немесе микрофонды қолданыңыз: алдымен қатысушыларды хабардар еткеніңізді растаңыз, браузерге микрофон рұқсатын беріңіз, жазуды бастаңыз және аяқтаңыз. Жазба тоқтағаннан кейін өңдеуге жіберіледі; бұл үздіксіз транскрипция емес.
5. **Жазба тілін** таңдаңыз: қазақша, орысша немесе аралас. Интерфейс тілі мен жазба тілі — екі бөлек параметр.
6. Алғашқы сынаққа **«Алғашқы 60 секунд»** таңдаңыз. Қажет болса, 10 минутқа дейінгі толық жазбаны өңдеңіз. 60 секунд таңдау бастапқы файлдың 10 минуттық шегін жоймайды: ұзағырақ файлды алдын ала бөліңіз.
7. Сөйлеушілер санын автоматты қалдырыңыз немесе белгілі санды көрсетіңіз. Қатысушылар жазу және ЖИ арқылы өңдеу туралы хабардар екенін растаған соң **«Өңдеуді бастау»** басыңыз. Қолданба бұл хабарламаны қатысушыларға өзі жібермейді.
8. Өңделген үзіндіні және жеке дауыс үлгілерін тыңдаңыз. Дауыс топтарына есім беріп, танылған мәтінді түзетіңіз. `SPEAKER_…` белгісі нақты адамның расталған аты емес.
9. Хаттаманы қалыптастырыңыз. ЖИ қысқаша қорытындыны, тапсырмаларды, орындаушыларды және мерзімдерді ұсынады; нәтиже архивке автоматты түрде сақталады.
10. Нәтижені оқып, **«Өңдеу»** арқылы қажет жерін түзетіңіз. Тексерілген соң тиісті белгіні қойып сақтаңыз және **DOCX** жүктеңіз.

ЖИ тапсырма беруші мен орындаушыны, мерзімді немесе іс-әрекетті шатастыруы мүмкін. Тапсырмадағы негізді ашып, бастапқы репликамен салыстырыңыз. Реплика сілтемесінің бар болуы тапсырманың мағынасы міндетті түрде дұрыс дегенді білдірмейді.

Өңдеу терезесін жабуға болады: сервер жұмысты жалғастырады, архивті қарай аласыз. Сол браузер қойындысын жаңартқанда ағымдағы жұмыс идентификаторы қалпына келеді. Серверді тоқтату аяқталмаған өңдеуді үзеді; ол кейін автоматты жалғаспайды.

### Дайын мәтіннен хаттама алу

«Жаңа жиналыс» ішінде **«Мәтін»** қойындысын таңдаңыз. Әр репликаны жеке жолға `Аты: мәтін` түрінде енгізіңіз, тексеріп, хаттаманы қалыптастырыңыз. Бұл режим аудио тану мен диаризацияны өткізіп жібереді, бірақ тапсырмалар мен қорытындыға жергілікті Qwen моделі қажет.

### Архив, тапсырмалар және еске салғыштар

| Бет | Не жасауға болады? |
|---|---|
| **Шолу** | Нақты сақталған хаттамалар/тапсырмалар санын, соңғы жиналыстарды, шұғыл тапсырмаларды көру |
| **Хаттамалар** | Атауы бойынша іздеу, тексерілген/тексерілмегенін сүзу, күнін/уақытын көру, таңдап ашу және жүктеу |
| **Хаттама беті** | Қорытындыны, репликаларды, тапсырма негіздерін көру; мазмұнын түзету; DOCX алу |
| **Тапсырмалар** | Мәтіні, жауапты адам немесе жиналыс атауы бойынша іздеу; мәртебесін өзгерту; кешіккенін сүзу |

Еске салғыштар орындалмаған, мерзімі өткен немесе бүгіннен бастап алдағы үш күнге белгіленген тапсырмаларға көрсетіледі. Шолу/тізім беті ашық, диалог пен белсенді өңдеу жоқ кезде олар минут сайын жаңарады. Бұл — қолданба ішіндегі ескерту; email, мессенджер немесе жүйелік push жіберілмейді. Мерзімі белгісіз тапсырма автоматты түрде кешіккен болып саналмайды.

## 5. Қайталауға болатын оқу мысалы

Алдымен қысқа **мәтіндік** сценарий арқылы модельді, сақтауды және DOCX алуды тексеруге болады. Барлық есімдер мен оқиға — синтетикалық мысал.

1. Интерфейсті **РУС** тіліне ауыстырыңыз: төмендегі орысша мысал осы тілдік нұсқаумен тексерілген.
2. Жаңа жиналыстың атауын «Оқу жиналысы», күнін **2026-09-23** деп қойыңыз.
3. «Мәтін» бөліміне енгізіңіз:

```text
Олег: Мария, отправь готовый отчет завтра.
Мария: Хорошо, отправлю завтра.
```

4. Репликаларды тексеріп, хаттама жасаңыз. Тексерілген прогонда бір тапсырма — дайын есепті жіберу, орындаушы — Мария, бастапқы мерзім — «завтра», күн — **2026-09-24** шыққан. Жаңа нәтижені де қолмен салыстырыңыз.
5. Хаттаманы тексерілген деп белгілеп, DOCX жүктеңіз. Бетті жаңартып, архивтен қайта ашыңыз; жасалған уақыты сақталуы керек.
6. Тапсырманы орындалды деп белгілеп, жалпы көрсеткіштердің өзгеруін қараңыз.

Қазақша/орысша аралас оқу мәтіні: [examples/mixed_meeting.txt](examples/mixed_meeting.txt). Оның соңғы нұсқадағы сапасы қайта өлшенген жоқ; салыстыру мен қателерді табуға қолданыңыз. Аудио мүмкіндігін көрсету үшін бөлек қысқа оқу жазбасын өңдеу қажет — мәтіндік сценарий аудио дәлдігін дәлелдемейді.

## 6. Сақтау, құпиялылық және резервтік көшірме

Дайын хаттама `data/protocols.sqlite3` базасына автоматты жазылады. Оның ішінде атауы, жиналыс күні, транскрипт, қорытынды, тапсырмалар және DOCX бар. Сақталған және соңғы өзгертілген уақыт Алматы уақыт белдеуімен тіркеледі. Өңдегенде бастапқы уақыт өзгермейді; жиналыс күні сақталған күнмен алмастырылмайды.

Архив браузердің уақытша жадына тәуелді емес: серверді қайта іске қосқанда құжаттарды қайта ашуға болады. Бірдей атаулы жиналыстар бөлек идентификатормен сақталады. Екі терезеден бір хаттаманы қатар түзеткенде ескірген нұсқа үндемей үстінен жазылмайды — бетті жаңарту қажет болады.

Аудио қолданба тарапынан сервер дискісіне сақталмайды. Микрофон жазбасы әуелі браузер жадында болады, кейін жергілікті серверге жіберіледі. Сервер соңғы төртке дейінгі өңдеу жұмысын, соның ішінде уақытша аудионы жадта ұстайды; бір сағаттан ескі жұмыстар **келесі жұмыс басталғанда** тазаланады. Демек бір сағат өткен сәтте автоматты жоюға кепіл жоқ. Сервер тоқтағанда уақытша жад босайды. Пайдаланушы жүктеген бастапқы файл өз орнында қалады.

Кодта сыртқы ЖИ API шақырулары, сыртқы шрифттер немесе аналитика жоқ. `start.sh` модель кітапханаларының офлайн режимін қосады; модельдер жергілікті жолдардан ашылады. Интернет толық бұғатталған ортадағы жеке сынақ әлі орындалмаған.

База қолданба арқылы шифрланбайды; оны компьютердің файл рұқсаттары қорғайды. Жоба бір пайдаланушыға арналған, тіркелгі мен рөлдер жоқ. `.gitignore` базаны, модельдерді, жергілікті сынақ файлдарын және бірқатар медиа пішімдерін қоспайды; жаңа файл түрін не жеке деректі жариялар алдында `git status` арқылы құрамын тексеріңіз.

**Резервтік көшірме:** алдымен серверді Ctrl+C арқылы тоқтатыңыз. Архив кемінде бір рет ашылып, база жасалғаннан кейін `khattama-ai` қалтасынан:

```bash
mkdir -p "$HOME/Documents/Khattama-backups"
cp -n data/protocols.sqlite3 "$HOME/Documents/Khattama-backups/protocols-$(date +%Y%m%d-%H%M%S).sqlite3"
```

Бұл команда уақыт белгісі бар бөлек көшірме жасайды. `Documents` бұлтпен синхрондалса, ұйымның сақтау талабына сәйкес басқа жергілікті қалтаны таңдаңыз. Қалпына келтіруде сервер жабық болуы, қазіргі базаға алдымен жеке көшірме жасалуы керек; архивті басқару мен қалпына келтіру батырмасы интерфейсте әзірге жоқ.

### Өңдеу кезеңдері

| Кезең | Іске асырылуы |
|---|---|
| Аудионы оқу | PyAV → 16 кГц, моно; ұзақ жазбаларға 10 минуттық шек |
| Сөзді тану | faster-whisper, Whisper small, CPU INT8, 2 ағын; сөз уақыттары; 30 секундтық бөліктер |
| Дауыстарды бөлу | Sherpa-ONNX, pyannote segmentation 3.0, NeMo TitaNet Small; сөздерді уақыт қабысуы бойынша дауысқа байланыстыру |
| Адам тексеруі | Репликаларды түзету, дауыс тобына есім беру; қабаттасқан дауыстар қате болуы мүмкін |
| Тапсырмаларды шығару | Qwen2.5-3B-Instruct GGUF Q4_K_M, llama-cpp-python; құрылымы шектелген JSON |
| Нәтижені тексеру | Реплика ID-лерін тексеру, белгісіз мәндерді сақтау, мерзімдерді нақтылау; мағыналық дәлдікке адам тексеруі қажет |
| Сақтау және құжат | SQLite транзакциясы; python-docx арқылы құжат қалыптастыру |

Qwen параметрлері: контекст `8192`, кіріс шегі шамамен `4600` токен, жауап шегі `3072`, `n_gpu_layers=0`, `offload_kqv=False`. Кіріс не жауап сыймаса, қолданба мәтінді бөліп қайта өңдеуді сұрайды. 10 минуттық аудионың мәтіні осы шекке міндетті түрде сыяды деген кепіл жоқ.

Мерзімнің сөйленген нұсқасы (`deadline_raw`) мен күнтізбелік күні (`due_date`) бөлек сақталады. «Бүгін/ертең» үшін жиналыс күні қажет; екіұшты мерзімдерді пайдаланушы нақтылайды. Кейде модель түсіріп кеткен жалғыз салыстырмалы мерзімді бір тапсырма/бір реплика жағдайында ереже қалпына келтіреді; ол тексеру ескертпесімен беріледі. Бұл — модель дәлдігі туралы мәлімдеме емес, қосымша өңдеу ережесі.

Сервер бір мезгілде бір модельдік жұмысты орындайды. Интерфейс бос архивке ойдан дерек қоспайды: көрсеткіштер SQLite жазбаларынан есептеледі. Негізгі іске қосу `server.py` қолданады; `app.py` бұрынғы нұсқа мен регрессиялық тесттер үшін сақталған.

### Негізгі HTTP маршруттары

| Әдіс және жол | Мақсаты |
|---|---|
| `GET /api/health` | Сервер күйі және модель файлдарының бары |
| `GET /api/dashboard` | Хаттамалар, тапсырмалар және көрсеткіштер |
| `POST /api/transcript` | Енгізілген мәтінді репликаларға бөлу |
| `POST /api/jobs/audio` | Файлдан аудио өңдеу жұмысын бастау |
| `POST /api/jobs/report` | Тексерілген репликалардан хаттама жасау |
| `GET /api/jobs/<id>` | Фондық жұмыстың кезеңі және нәтижесі |
| `GET /api/protocols/<id>` | Сақталған хаттама |
| `GET /api/protocols/<id>/docx` | DOCX жүктеу |
| `GET /api/protocols/<id>/json` | Құрылымдалған деректі алу |
| `POST /api/protocols/<id>` | Хаттаманы немесе тапсырма мәртебесін жаңарту |

Бұл — жергілікті интерфейстің API-ы. Өзгерту сұраулары `X-Khattama-Request: 1` тақырыбын талап етеді; `Host` пен `Origin` тексеріледі, құжат жаңартқанда нұсқа сәйкестігі қолданылады. Дерек пішімінің мысалдары [tests/test_server.py](tests/test_server.py) ішінде. Бұл тексерулер тіркелгі жүйесін немесе өндірістік серверді алмастырмайды.

## 8. Қалай тексереді?

### Кітапханалар және Python тесттері

```bash
.venv/bin/python doctor.py
.venv/bin/python -m pip check
.venv/bin/python -m unittest discover -s tests -v
```

Соңғы тіркелген нәтиже: **18 тест өтті, 9,317 секунд**. Тесттер мерзімдерді, сөйлеуші уақыттарын, DOCX мазмұнын, архивті, HTTP әрекеттерін және бұрынғы интерфейстің регрессияларын қамтиды. Олар толық ЖИ сапасының бағасы емес. Нақты прогон жағдайлары [VALIDATION.md](VALIDATION.md) ішінде.

### Браузер сценарийі — әзірлеушіге

Күнделікті қолдануға Playwright қажет емес. Интерфейсті тексеру үшін жеке ортада:

```bash
python3 -m venv /tmp/khattama-browser
/tmp/khattama-browser/bin/python -m pip install playwright==1.48.0
/tmp/khattama-browser/bin/python -m playwright install chromium
/tmp/khattama-browser/bin/python tests/browser_check.py
```

Алғашқы орнату интернетті қажет етеді. Скрипт бос портта жеке тест серверін және уақытша базаны ашады; пайдаланушы архивіне сынақ хаттамаларын қоспайды. Модель жауабы мен микрофон дерегі синтетикалық, ал HTTP, формалар, SQLite және DOCX тізбегі нақты орындалады.

Сценарий: мәтін енгізу → репликаны түзету → хаттама → DOCX → редакциялау → бетті жаңарту → жауаптыны іздеу → мәртебе → тіл ауыстыру → аудио/микрофон жолы → сөйлеуші есімі → сақтау. 320/390/768/1440 px көріністерінің скриншоттары мен сынақ құжаты `.local-validation/ui/` ішіне түседі.

### Нақты ЖИ сапасын тексеру

Орысша, қазақша және аралас қысқа оқу жазбаларын өңдеңіз. Қолмен жазылған эталонмен сөздерді, сөйлеушілерді, тапсырмаларды, жауаптылар мен мерзімдерді салыстырыңыз. Толық өңдеу уақытын және қателерін тіркеңіз. [evaluation/meeting_reference_checks.json](evaluation/meeting_reference_checks.json) салыстыруға арналған; ол модель жауабына салынбайды.

Mac-та нақты жазбаның 60 секундын тану **67,45 с**, диаризация **26,37 с** алған. Жеке қысқа мәтінде Qwen орысша сценарийді **88,99 с**, қазақша сценарийді **119,72 с** өңдеген; қазақша нәтижеде мерзім мен қорытынды қатесі болды. Бұл бөлек сынақтарды қосып, толық бір жиналыстың өлшенген уақыты деп көрсетуге болмайды.

## 9. Linux, басқа компьютер және телефон

Linux-та `install_mac.sh` атауына қарамастан жеке Linux тармағы бар: `requirements.txt` қолданылады, llama-cpp-python CPU үшін бастапқы кодтан жиналады. Python 3.9+, `venv`, gcc/g++, құрастыру құралдары қажет.

Ubuntu/Debian үшін жүйелік тәуелділіктерді дайындау мысалы:

```bash
sudo apt update
sudo apt install git python3 python3-venv python3-dev build-essential cmake
```

Одан кейін [Mac нұсқаулығындағы](#install) репозиторийді алу, `bash install_mac.sh`, модель жүктеу, диагностика және іске қосу қадамдары орындалады. Бұрынғы өңдеу тізбегі Linux x86_64 / Python 3.12-де тексерілген; жаңа веб-нұсқаның толық Linux орнатуы бөлек расталмаған. Windows, WSL және Apple Silicon үшін де жеке толық тексеру жасалған жоқ.

GPU-ы бар компьютерге немесе NVIDIA/Brev серверіне көшіру CUDA-ны автоматты қоспайды: қазіргі код CPU-ға бекітілген. Жабық GPU серверіне бейімдеу — [дамыту жоспарының](../README.md#roadmap) бөлігі.

**Телефонда ашу:** интерфейс шағын экранға бейімделеді, бірақ сервер тек өз компьютеріндегі `127.0.0.1` мекенжайын тыңдайды. Телефондағы `127.0.0.1` Mac-ты көрсетпейді. Басқа құрылғыдан кіру үшін сервердің желі баптауы, HTTPS және пайдаланушы рұқсаттары бөлек әзірленуі керек; қазіргі нұсқада оны іске қосатын дайын команда жоқ. Микрофон үшін localhost немесе HTTPS контексті және браузер рұқсаты қажет.

## 10. Жиі кездесетін мәселелер

| Белгі | Не істеу керек? |
|---|---|
| `start.sh` немесе `.venv/bin/python` табылмады | `khattama-ai` қалтасында екеніңізді тексеріңіз; орта жоқ болса `bash install_mac.sh` орындаңыз |
| `MODEL … не скачана` / модель дайын емес | `prepare_models.py` не тиісті `--only` командасын орындап, `doctor.py` нәтижесін қайта қараңыз |
| `No matching distribution found` | Python нұсқасын және `uname -m` нәтижесін салыстырыңыз; арнайы Mac жинағы Intel / Python 3.9 үшін тексерілген, басқа комбинацияға бөлек тәуелділік таңдау қажет болуы мүмкін |
| `_OBJC_CLASS_$_MLComputePlan` қатесі | macOS 12 Intel / Python 3.9 үшін `bash install_mac.sh` қолданыңыз: `requirements-mac.lock` Sherpa-ONNX 1.10.46-ны бекітеді; 1.12.40 бұл Mac-та импортталмады |
| `Address already in use` | Бұрынғы сервердің терминалында Ctrl+C басыңыз немесе `.venv/bin/python server.py --port 8502` қолданып, 8502 мекенжайын ашыңыз |
| Браузер серверге қосылмайды | Сервер терминалы ашық екенін және соңғы қатені қараңыз; `curl http://127.0.0.1:8501/api/health` орындаңыз |
| Микрофон қосылмайды | Қатысушыларды хабардар ету белгісін, браузер/жүйе микрофон рұқсатын және localhost мекенжайын тексеріңіз; файл жүктеу жолын да қолдануға болады |
| Өңдеу ұзақ | Алғашқы 60 секундтан бастаңыз, басқа ауыр қолданбаларды жабыңыз; CPU-да бір жұмыс қана орындалады |
| Ұзын файл 60 секунд режимінде де өтпейді | Бастапқы файлдың өзі 10 минуттан аспауы тиіс; алдын ала бөліңіз |
| Мәтін ұзын / жауап сыймады | Репликаларды мағыналық бөліктерге бөліп, жеке хаттама ретінде өңдеңіз; автоматты біріктіру әзірге жоқ |
| Сөз немесе сөйлеуші қате | Жазба тілін, дауыс санын тексеріңіз; репликалар мен есімдерді түзетіңіз; қабаттасқан дауысқа ерекше назар аударыңыз |
| Орындаушы, мерзім немесе қорытынды қате | Бастапқы репликамен салыстырыңыз; жиналыс күнін бастапқы қадамда дұрыс беріңіз; дайын тапсырманы редакторда түзетіңіз |
| Хаттама басқа терезеде өзгертілген | Бетті жаңартып, соңғы нұсқаны ашып түзетіңіз |
| Уақытша өңдеу дерегі аяқталған | Жазбаны қайта жүктеңіз; сақталып үлгерген хаттама архивте қалады |
| Жаңартылған интерфейс көрінбейді | Серверді қайта іске қосып, Mac-та браузерді **⌘⇧R** арқылы жаңартыңыз |

Тексерілген Mac-та Metal-дың кейбір ядролары өткізіліп жіберілгені және `CoreMLExecution` қайталануы туралы ескертулер болған; CPU сынағы соған қарамастан аяқталған. Ескертуді толық traceback қатесінен ажыратыңыз: өңдеу тоқтаса, терминалдағы нақты қатені тексеру қажет.

## 11. Қазіргі шектеулер

- Қазақша және аралас **аудио** сапасы өлшенбеген. Қысқа қазақша мәтіннен тапсырма мен орындаушы табылғанымен, мерзім түсіп қалып, қорытынды дәл болмаған. Қолмен тексеру қажет.
- Аралас режим тілді 30 секундтық бөліктерде анықтайды; бір бөліктің ішіндегі ауысуларды жоғалтуы мүмкін.
- Диаризация дауыстарды топтайды, адамның тұлғасын автоматты растамайды. Қабаттасқан сөйлеу мен шулы жазбада қате болуы мүмкін.
- Екі толық жиналыс барлық тізбектен өткізілмеген; WER, DER, тапсырма дәлдігі және толық сценарийдің ең жоғары жад шығыны өлшенбеген.
- DOCX құрылымы мен мазмұны Python арқылы қайта ашылып тексерілген; ұзын құжаттың Word/Pages-тағы көрінісі бөлек расталмаған. PDF әзірге жоқ.
- Teams/Zoom/Meet боты, тікелей ағын транскрипциясы, дауыс биометриясы, сыртқы еске салғыштар және ЭҚАЖ интеграциясы іске асырылмаған. Осы платформалардан алынған дайын жазбаны жүктеуге болады.
- Бір пайдаланушыға арналған жергілікті сервер; тіркелгілер, рөлдер, HTTPS және база шифрлауы жоқ. Нақты мобильді құрылғылар мен Safari бөлек сыналмаған.

Ұсынылған келесі қадамдар, басымдықтар және бағалау өлшемдері [дамыту жоспарында](../README.md#roadmap).
